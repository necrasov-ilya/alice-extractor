# Подготовка смешанных int8/BF16 весов

Alice Extractor использует собственный формат контрольной точки для запуска AliceAI-T5 на Apple Silicon. Матрицы `w1`, `v1` и `w2` каждого эксперта квантуются симметрично до int8 с отдельным масштабом для каждой строки. Остальные параметры сохраняют исходный тип BF16.

Для строки весов `w` масштаб вычисляется как `max(abs(w)) / 127`. Квантизированное значение получается округлением `w / scale` в диапазоне от -127 до 127. Нулевые строки получают минимальный положительный масштаб `1e-8`.

## Воспроизводимый запуск

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e .

.venv/bin/alice-quantize-checkpoint \
  --repo-id yandex/AliceAI-T5-35B-A0.6B \
  --revision a0d71f58c40d6affe461797b30b35ff47f52a5f2 \
  --model-dir local/aliceai-t5/model \
  --source-dir local/aliceai-t5/data/source \
  --output-dir local/aliceai-t5/data/int8
```

Команда сначала получает небольшие файлы конфигурации, код архитектуры, токенизатор и индекс весов. Затем она обрабатывает 15 частей контрольной точки последовательно. В каждый момент на диске требуется место для готовых производных весов и одной исходной части. Успешно обработанная исходная часть удаляется. Флаг `--keep-source-shards` сохраняет её, а `--force` заменяет уже готовые производные части.

В каталоге результата создаются `quantization_config.json`, `quant_model.safetensors.index.json` и `SHA256SUMS`. Они фиксируют формат, точную ревизию источника, расположение каждого тензора и контрольную сумму каждой части. Публикация весов также включает код архитектуры исходной ревизии, лицензию и уведомления Yandex.

## Проверка перед публикацией

1. Убедиться, что созданы все 15 файлов `quant_model-*.safetensors`.
2. Запустить модуль на MPS и проверить загрузку всех параметров без пропусков.
3. Сравнить ответы с исходным путем на неизменяемой части набора данных.
4. Зафиксировать точность полей, валидность JSON и скорость обоих путей.
5. Загрузить производные веса только после прохождения проверки качества.

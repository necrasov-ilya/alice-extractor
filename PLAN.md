# План Alice Extractor

## Цель

Построить открытый экстрактор, который получает запрос и найденные документы, а возвращает минимальный контекст, достаточный AliceAI-T5 для правильного ответа. Экстрактор оптимизируется под целевую генеративную модель, поэтому релевантность фрагмента определяется не только его близостью к запросу, но и фактическим влиянием на ответ.

Первая версия работает с готовым текстом. Получение документов из поисковой системы, разбор PDF и распознавание изображений в эксперимент не входят.

## Этап 0. Воспроизводимый запуск AliceAI

1. Зафиксировать исходную ревизию модели и версии зависимостей.
2. Хранить локальные и производные веса только в исключённом из Git каталоге `local`.
3. Загружать смешанную контрольную точку int8/BF16 на Apple Silicon.
4. Вычислять только выбранных маршрутизатором экспертов.
5. Раздельно измерять кодирование входа, первый шаг декодера и дальнейшую генерацию.

Этот этап реализован. Опубликованные измерения не используются как заявление о преимуществе над исходной моделью или другими средами выполнения.

## Этап 1. Набор поисковых задач

1. Собрать 2 000 обучающих, 300 проверочных и 300 тестовых запросов.
2. Для каждого запроса сохранить несколько документов, эталонный ответ и подтверждающие фрагменты.
3. Разделить источники между выборками, чтобы одинаковые документы не попадали в обучение и тестирование.
4. Проверить ссылки, границы фрагментов, дубликаты и наличие ответа в источниках.
5. Сохранить происхождение и лицензию каждого документа.

Формат записи определён в [docs/data-format.md](docs/data-format.md). Тестовая часть фиксируется до обучения экстрактора.

## Этап 2. Получение модельно-зависимых целей

1. Разбить документы на предложения и короткие смысловые фрагменты.
2. Построить несколько вариантов сокращённого контекста для каждого запроса.
3. Оценить каждый вариант по потере AliceAI на эталонном ответе и штрафу за длину.
4. Получить мягкую вероятность полезности каждого фрагмента по лучшим вариантам.
5. Сохранить полную трассировку разметки: ревизию AliceAI, шаблон запроса, параметры отбора и оценки.

Полная генерация ответа нужна только для итоговой проверки. При построении большей части целей используется оценка фиксированного эталонного ответа, чтобы сократить стоимость разметки.

## Этап 3. Обучение экстрактора

1. Взять русскоязычный кодировщик размером 50–150 млн параметров.
2. Подавать на вход запрос и документ с границами фрагментов.
3. Обучать вероятность сохранения фрагментов по мягким целям.
4. Выбирать порог по проверочной части отдельно для нескольких бюджетов контекста.
5. Зафиксировать один выпуск модели до открытия итоговой части данных.

Одна RTX 3090 достаточна для этого этапа. AliceAI остаётся замороженной и используется только для построения целей и оценки.

## Этап 4. Сравнение

Сравниваются:

- полный контекст
- случайный отбор той же длины
- BM25
- векторный поиск
- модель повторного ранжирования
- модельно-зависимый экстрактор

Для каждого метода измеряются правильность ответа, сохранность подтверждений, доля оставшихся токенов, фактические ошибки, время кодирования и полная задержка. Результаты публикуются для бюджетов 5, 10, 20 и 50 процентов исходного контекста.

## Этап 5. Публикация

В GitHub публикуются код подготовки данных, обучение, базовые методы, оценка и воспроизводимые конфигурации. В Hugging Face отдельно публикуются набор поисковых задач и обученный экстрактор. Веса AliceAI и локальные кэши в GitHub не добавляются.

## Ближайшие задачи

1. Собрать проверочный набор из 100 запросов и измерить стоимость разметки.
2. Реализовать разбиение документов на устойчивые фрагменты.
3. Добавить оценку эталонного ответа AliceAI без генерации.
4. Реализовать BM25 и векторный поиск как базовые методы.
5. Зафиксировать критерии качества до обучения экстрактора.

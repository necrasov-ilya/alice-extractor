# План Alice Extractor

## Цель

Проверить, можно ли превратить AliceAI-T5-35B-A0.6B Base в воспроизводимый локальный инструмент извлечения структурированных данных из русскоязычных документов. Первая версия ограничивается счетами. Договоры, акты и резюме добавляются только после подтверждения качества и производительности на первой категории.

Главный результат первого этапа — не интерфейс, а честный ответ на три вопроса: насколько точно AliceAI извлекает заданные поля, насколько ей помогают шаблоны с примерами и имеет ли она практическое преимущество перед Qwen 3.5 35B-A3B на том же компьютере.

## Этап 0. Зафиксировать воспроизводимую основу

1. Сохранить оригинальную модель и локальные int8-веса только в каталоге `local`, исключённом из Git.
2. Зафиксировать Python 3.12 и проверенные версии PyTorch, Transformers, Safetensors и Accelerate.
3. Переделать пути загрузки модели на параметры конфигурации. Публикуемый код не должен зависеть от абсолютных путей конкретного компьютера.
4. Добавить команды проверки наличия 15 шардов и необходимых файлов конфигурации.
5. Разделить измерения на время кодирования входа, задержку первого выходного токена, скорость последующих токенов и пиковую память.

Результат этапа: любой пользователь с совместимым Mac и самостоятельно загруженными весами может воспроизвести запуск по документации.

## Этап 1. Исправить путь выполнения на Apple Silicon

1. Заменить вычисление всех 512 экспертов при многотокенном проходе на обработку только восьми выбранных экспертов с ограничением размера временных буферов.
2. Убрать преобразование всей матрицы выходного слоя в float32 при каждом токене на MPS. Выбранный вариант должен пройти сравнение логитов и итоговых ответов.
3. Проверить корректность кеша декодировщика и повторное использование ключей и значений перекрёстного внимания.
4. Добавить тесты численной близости с исходной реализацией на коротких последовательностях.
5. Зафиксировать результаты до и после изменений на одном наборе запросов.

Текущая реализация добавлена как отдельный модуль и проверена численным тестом экспертного слоя. На M1 Max прогретое кодирование входа из 57 токенов сократилось с 8,042 до 1,451 секунды. Первый проход декодера сократился с 1,403 до 0,293 секунды. Полное сравнение ответов по набору документов ещё не выполнено.

## Этап 2. Провести проверочный эксперимент

1. Подготовить 50 счетов. Допускаются собственные синтетические документы и материалы с явно разрешённым распространением.
2. Зафиксировать схему полей: номер, дата, поставщик, покупатель, ИНН сторон, валюта, сумма без НДС, НДС, итоговая сумма и позиции.
3. Разделить набор на 30 документов для разработки шаблонов, 10 для проверки решений и 10 для финальной оценки.
4. Сравнить три подхода: правила, выбранную контрольную модель Qwen и AliceAI-T5-35B-A0.6B.
5. Для AliceAI отдельно измерить голую модель, статический шаблон и шаблон с несколькими примерами.
6. Считать валидность JSON, точность каждого поля, совокупную F1, подтверждаемость значений исходным текстом и задержки выполнения.

Решение о продолжении принимается по результатам. Продукт на AliceAI развивается, если модель показывает приемлемое качество и хотя бы одно подтверждённое преимущество. Если Qwen одновременно точнее, быстрее и проще в эксплуатации, проект меняет фокус на открытый MPS-запуск AliceAI и исследование её базовых возможностей.

## Этап 3. Собрать первую рабочую версию продукта

1. Реализовать внутренний формат документа без привязки к PDF.
2. Добавить компилятор шаблонов, проверку результата по JSON Schema и привязку значений к фрагментам исходного текста.
3. Предоставить локальный программный интерфейс и команду обработки одного документа.
4. Добавить простой локальный веб-интерфейс после стабилизации ядра.
5. Подключить извлечение текста из PDF отдельным модулем. Распознавание изображений не входит в первую версию.
6. Сохранять исходный ответ модели, нормализованный результат и отчёт проверки для разбора ошибок.

## Этап 4. Опубликовать результаты

### GitHub

В GitHub публикуются исходный код, схемы, шаблоны, тесты, сценарии загрузки и квантизации, воспроизводимые измерения, архитектурные решения и документация. Базовые веса, локальные клоны Hugging Face, приватные документы, кеши и окружения в Git не попадают.

Первый выпуск должен содержать рабочую команду извлечения, проверку схемы, минимум 50 тестовых документов или ссылку на версионированный набор Hugging Face, сравнительную таблицу и инструкции воспроизведения на Apple Silicon.

### Hugging Face

Первой публикацией становится отдельный набор данных с карточкой происхождения, лицензией, описанием полей и неизменяемым тестовым разделом. Репозиторий модели создаётся только при наличии дообученного адаптера или самостоятельных производных весов, которые действительно нужно распространять. В таком репозитории указываются точная базовая модель, версия данных, параметры обучения, ограничения и результаты оценки.

Публичный репозиторий `necrasov-ilya/AliceAI-T5-35B-A0.6B-MPS-ExpertInt8` уже создан. Его карточка связывает производную модель с `yandex/AliceAI-T5-35B-A0.6B` через поля `base_model` и `base_model_relation: quantized`. Веса будут отправлены после проверки качества. Запланированные имена остальных публикаций: `necrasov-ilya/ru-invoice-extraction-benchmark` для набора данных и `necrasov-ilya/alice-extractor` для демонстрации.

Space публикуется после появления доступной вычислительной среды. Демонстрация не должна скрывать удалённую модель, подменять результаты заранее сохранёнными ответами или обещать производительность, которая не воспроизводится пользователем.

## Что не входит в первую версию

- универсальный чат-помощник
- поддержка любых типов документов
- распознавание отсканированных изображений
- обучение на закрытых пользовательских документах
- публикация базовых или локально квантизированных весов в GitHub
- заявления о превосходстве без фиксированного тестового набора

## Ближайшие задачи

1. Опубликовать принятую версию синтетического набора счетов и зафиксировать его ревизию.
2. Реализовать оценку ответов модели по полям, валидности JSON и подтверждаемости значений.
3. Сравнить ответы исходного и маршрутизируемого путей на всём проверочном наборе.
4. Зафиксировать точный идентификатор и конфигурацию контрольной модели Qwen.
5. Получить сопоставимые показатели AliceAI, Qwen и системы правил.
